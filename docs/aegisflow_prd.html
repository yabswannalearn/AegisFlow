1. Executive Summary & Architectural Problem SEC-01

US telehealth providers face a critical compliance bottleneck when integrating modern LLM triage agents and marketing CRMs like HubSpot. Standard low-code automation pipelines transmit raw Protected Health Information (PHI) directly into third-party AI training logs and unencrypted CRM properties, violating HIPAA privacy mandates and TCPA telemarketing consent laws.

Next.js Client & Server BFF (The HIPAA Vault)

Acts as the deterministic security boundary. Handles patient intake, TCPA/HIPAA consent logging, AES-256-GCM field-level encryption in PostgreSQL, regex PII scrubbing, immutable audit logging, and clinician Role-Based Access Control (RBAC).

Self-Hosted n8n Engine (Stateless Orchestrator)

Receives strictly anonymized payloads via HMAC-signed webhooks. Executes the AI Triage Agent with tool-calling, syncs HubSpot CRM pipelines using Vault reference URLs, and orchestrates closed-loop patient onboarding.

4. Functional Requirements: Modules 1 to 3 (Intake to HITL Approval) SEC-04

Module 1: Patient Lead Generation & Compliant Intake (/intake)

  • [FR-1.1] Multi-Part Intake Capture: Captures Patient Demographics (Full Name, Email, Phone, DOB), Insurance Info (Payer Name, Member ID, Group Number), Clinical Symptoms (free text), and explicit checkboxes for HIPAA Authorization and TCPA SMS Opt-In.
  • [FR-1.2] Legal Consent & Audit Persistence: Server Action validates input via Zod, records client IP, User-Agent, UTC timestamp, and policy version in ConsentRecord, and writes an immutable AuditLog (ACTION: INTAKE_SUBMITTED).
  • [FR-1.3] Envelope Encryption & Deterministic Scrubbing: Raw PII and clinical notes are encrypted with AES-256-GCM before saving to PatientVault. The server then runs scrubSymptoms() to replace names, dates, phones, emails, and SSNs with anonymized tokens before firing n8n Workflow #1:
// POST https://n8n.internal/webhook/aegis-triage (Headers: x-aegis-signature, x-aegis-timestamp) { "idempotency_key": "intake_99481a7b-3c2d-4e9f-8a1b", "patient_uuid": "99481a7b-3c2d-4e9f-8a1b-772190c8e112", "lead_contact": { "first_name": "Jane", "email": "jane.doe@example.com", "phone": "+15550192831" }, "insurance_provider": "Aetna_PPO", "scrubbed_symptoms": "Patient [REDACTED_NAME] (DOB: [REDACTED_DATE]) reports 4 days of chest tightness...", "vault_review_url": "https://aegisflow.demo/admin/vault/99481a7b-3c2d-4e9f-8a1b-772190c8e112" }

Module 2: Stateless AI Triage & HubSpot CRM Sync (n8n Workflow #1)

  • [FR-2.1] Cryptographic Verification & Idempotency: n8n verifies the HMAC-SHA256 signature and checks idempotency_key against Next.js to prevent duplicate execution on webhook retries.
  • [FR-2.2] AI Triage Agent with Tool Calling: The n8n AI Agent analyzes scrubbed_symptoms and invokes two bound HTTP tools: (1) check_insurance_eligibility (queries Next.js mock payer endpoint) and (2) fetch_clinical_routing_rules (maps symptoms to specialist tracks).
  • [FR-2.3] Structured Output Enforcement: The Agent enforces a strict JSON Schema Output Parser before updating HubSpot and calling back to Next.js (POST /api/webhooks/n8n-triage-callback):
{ "urgency_level": "HIGH", "recommended_specialty": "Cardiology", "triage_rationale_redacted": "Acute chest tightness lasting >72h warrants priority cardiac evaluation.", "insurance_verified": true, "copay_estimate_usd": 35, "suggested_onboarding_track": "FastTrack" }
  • [FR-2.4] Zero-PHI HubSpot Pipeline Sync: n8n upserts the HubSpot Contact (lifecyclestage = lead) and creates a Deal in the "Patient Intake Pipeline" (Stage: AI Triaged - Pending Clinician Review) populated strictly with non-clinical metadata and the vault_review_url pointer.

Module 3: Clinician HITL Vault & Magic Link Dispatch (/admin/vault/[id] ↔ n8n #2)

  • [FR-3.1] RBAC Authentication & Audited Decryption: When a clinician clicks vault_review_url inside HubSpot, Next.js verifies their staff session, inserts an append-only AuditLog row (ACTION: PHI_DECRYPTED_VIEW), and decrypts the raw clinical notes and AI triage card on the server.
  • [FR-3.2] One-Click Approval & Token Generation: Clicking "Approve & Start Onboarding" generates a cryptographically random one-time onboarding token (hashed via SHA-256 in Postgres with a 48-hour expiry) and triggers n8n Workflow #2.
  • [FR-3.3] HIPAA-Safe Multi-Channel Notification: n8n advances the HubSpot Deal stage to Approved - Onboarding Sent and sends an email/SMS via Resend containing zero medical info—only the secure magic link: https://aegisflow.demo/onboarding/{raw_token}.

5. Functional Requirements: Modules 4 & 5 (Closed-Loop Onboarding) SEC-05

Module 4: 3-Step Patient Onboarding Portal (/onboarding/[token] ↔ n8n Workflow #3)

  • [FR-4.1] Single-Use Token Validation: Navigating to /onboarding/[token] hashes the URL token with SHA-256 and verifies that the token exists in PatientVault, is unexpired (< 48h), and has status APPROVED.
  • [FR-4.2] Step 1 — KYC Identity & Insurance Card Confirmation: Patient uploads a photo ID and insurance card (includes a "Populate Demo Insurance Card" button for recruiters). Next.js encrypts the document metadata and logs ACTION: KYC_VERIFIED.
  • [FR-4.3] Step 2 — Telehealth Informed Consent & NPP E-Signature: Captures the patient's typed legal signature acknowledging the Notice of Privacy Practices (NPP) and Consent to Telehealth Treatment, storing the signature hash and IP in ConsentRecord.
  • [FR-4.4] Step 3 — Specialist Slot Booking & Final Webhook: Displays available time slots for the approved specialty (e.g., Cardiology). Clicking "Confirm Appointment" updates PatientVault.status = ONBOARDED and triggers n8n Workflow #3.
  • [FR-4.5] HubSpot Closed-Won & Customer Lifecycle Upgrade: n8n Workflow #3 transitions the HubSpot Deal stage to Closed Won - Appointment Booked, upgrades the HubSpot Contact lifecyclestage from lead to customer, writes the appointment_datetime property, and posts a confirmation alert to the clinic's Slack/Discord channel.

Module 5: "Developer X-Ray Mode" Live Telemetry UI (Portfolio Showcase Feature)

[FR-5.1] Real-Time 4-Stage Split-Screen Inspector

Accessible via a persistent header toggle so technical interviewers can inspect the full backend pipeline without leaving the browser. Submitting an intake or completing onboarding updates four live telemetry cards in real time via Server-Sent Events / polling: (1) Raw Browser Payload (highlights detected PII/PHI tokens in red), (2) PostgreSQL Vault Row (displays live AES-256-GCM ciphertext and the append-only AuditLog stream), (3) Scrubbed n8n Webhook Inspector (displays the exact JSON & HMAC signature sent to n8n), and (4) AI Agent & HubSpot Deal State (shows structured triage JSON and live CRM stage transitions).

6. Lightweight Security Core (~150 LOC Specification) SEC-06

1. Field Encryption (src/lib/crypto.ts)

Uses native Node.js crypto with aes-256-gcm. Every encrypted field generates a fresh 12-byte random IV and 16-byte authentication tag, stored in canonical format: v1:{iv_hex}:{authTag_hex}:{ciphertext_hex}.

2. Webhook Signing (src/lib/hmac.ts)

Signs all Next.js ↔ n8n payloads using HMAC-SHA256(secret, `${timestamp}.${rawBody}`). Requests with a timestamp drift exceeding ±300 seconds are rejected to prevent replay attacks.

7. Node-by-Node n8n Workflow Blueprints (Git-Tracked JSONs) SEC-07

All four n8n workflows are exported as declarative JSON files inside /n8n/workflows/ so code reviewers can inspect orchestration logic alongside the Next.js codebase.

7.1 Primary Triage & Lead Routing Workflow (triage-agent.json)

Node Order n8n Node Type Execution Logic & Configuration
Node 01 Webhook (POST) Listens on /webhook/aegis-triage. Passes raw body and x-aegis-signature / x-aegis-timestamp headers to Node 02.
Node 02 Code (TypeScript) Computes HMAC-SHA256 using $env.AEGIS_WEBHOOK_SECRET. Throws 401 Unauthorized if signature mismatches or timestamp is stale.
Node 03 AI Agent (Tools Agent) Connected to OpenAI Chat Model (gpt-4o-mini) + Structured Output Parser. Evaluates scrubbed_symptoms with zero-PII system prompt.
Node 04a/b HTTP Request Tool Bound tools invoked dynamically by Node 03: queries GET /api/mock/insurance?payer=... and GET /api/mock/routing-rules on Next.js server.
Node 05 HubSpot (Contact) Upserts Contact via email; sets lifecyclestage = lead, aegis_patient_uuid, and hipaa_consent_verified = true.
Node 06 HubSpot (Deal) Creates Deal associated with Contact in Patient Intake Pipeline; sets stage AI Triaged, ai_urgency, and vault_review_url.
Node 07 HTTP Request (POST) Signs and dispatches AI triage JSON + hubspotContactId + hubspotDealId back to Next.js /api/webhooks/n8n-triage-callback.

7.2 Secondary & Reliability Workflows SEC-07.2

Workflow #2: HITL Approval Dispatch onboarding-dispatch.json

Trigger: Clinician clicks Approve in Vault.
Nodes: Webhook → HMAC Verify → HubSpot Deal Update (Stage: Approved - Onboarding Sent) → Resend Email API (sends HIPAA-safe magic link /onboarding/{token}) → Next.js Audit Callback.

Workflow #3: Onboarding Completion onboarding-complete.json

Trigger: Patient completes 3-step onboarding.
Nodes: Webhook → HMAC Verify → HubSpot Deal Update (Stage: Closed Won) → HubSpot Contact Update (lifecyclestage: customer) → Slack Clinic Notification.

Workflow #4: Dead-Letter Error Handler error-dlq.json

Trigger: Global n8n Error Trigger node.
Nodes: Captures failed workflow ID, node name, and error message (stripping payload bodies) → Posts alert to Slack Ops channel → Calls Next.js /api/webhooks/n8n-error.

Retry & Backoff Policy Resilience Config

All external HTTP and HubSpot nodes in n8n are configured with Retry On Fail = true (Max 3 tries, 2000ms exponential wait) paired with WebhookIdempotency keys to guarantee at-least-once delivery without duplicates.

11. Security Threat Model (STRIDE Mitigation Matrix) SEC-11

Enterprise Threat Mitigations Built Into Architecture

1. Prompt Injection & PII Leakage to LLMs: Mitigated by running deterministic regex redaction (scrubber.ts) on the Next.js server before n8n or OpenAI receives the text, plus enforcing a strict JSON Schema Output Parser.
2. Webhook Spoofing & Replay Attacks: Mitigated via bidirectional HMAC-SHA256 signature headers bound to a 300-second timestamp window and tracked in WebhookIdempotency.
3. Third-Party CRM & Log Honeypots: Mitigated by withholding clinical PHI from HubSpot (storing only vault_review_url) and configuring Dockerized n8n with EXECUTIONS_DATA_SAVE_ON_SUCCESS=none.

14. Acceptance Criteria & Automated Verification Suite SEC-14

Gate 1: Zero-PII Leak Unit Test Vitest Suite

Automated test passes 25 synthetic clinical paragraphs containing names, SSNs, phones, emails, and DOBs through scrubSymptoms() and asserts 0% raw token survival.

Gate 2: Cryptographic Tamper Test Security Test

Verifies that modifying 1 byte of an AES-256-GCM ciphertext throws an authentication tag error, and sending an unsigned or stale webhook to n8n returns HTTP 401.

Gate 3: Audit Immutability Check DB Trigger Test

Executes DELETE FROM "AuditLog" and UPDATE "AuditLog" in integration tests and asserts PostgreSQL raises the custom HIPAA compliance exception.

Gate 4: Closed-Loop E2E Lifecycle Playwright E2E

Completes intake → AI triage → Clinician approval → Patient onboarding and verifies HubSpot Deal equals Closed Won and Contact equals customer.
